# Rules for worker agents

You are one of several coding agents working in parallel under an orchestrator. Read this once, then follow it exactly.

1. **Work only in your worktree.** Create it with `scripts/worktree.sh <repo> <beads-id> <slug>`; it prints the path and puts you on branch `maint/<beads-id>-<slug>`. Never edit the main checkouts under `repos/` and never touch another task's worktree.
2. **Never run `bd` write commands, never push, never merge, never touch `maint-2026`.** The orchestrator owns beads, merges and remotes. Report what you did in your final message instead.
3. **Commit small, commit often, gate before every commit.** One logical change per commit (one dependency removal, one batch of build files). Run the repo's gate script before each commit and include the gate result in the commit message body. Message format: `<area>: <summary> [<beads-id>]`, body: what/why, gate result, then `Co-Authored-By: Claude <model> <noreply@anthropic.com>`. Commits are made with the git identity already configured globally.
4. **Gate scripts** live in `repos/intermine-planning/scripts/`: `gate-intermine.sh`, `gate-bluegenes.sh` (read the usage header of each). For intermine, create your isolated test environment first with `scripts/im-testenv.sh <beads-id>`.
5. **Dependency hygiene (Gos's rules).** Remove a library rather than upgrade it when it is used in one place or only for something the standard library provides; use judgement if it is used in a few places but easy to remove. Each removal is its own commit. If you swap a package for a *different* one, first read its source and release history for malware indicators (install scripts, network calls, eval on untrusted input, obfuscation, binary blobs) and for convoluted code; record the vet in `repos/intermine-planning/decisions/package-vetting.md` even when safe; a failed vet blocks the swap. In Gradle files prefer task input/output wiring over explicit `dependsOn`; keep `dependsOn` only for genuine lifecycle ordering and comment why.
6. **Resources.** The sandbox has 15 GB RAM shared with other agents. Gradle: `-Xmx4g`, `--max-workers=4`. Do not start Docker stacks unless your task says so. Do not install system packages unless your task says so.
7. **Toolchain notes.** JDKs: `/usr/lib/jvm/java-{8,11,17,21}-openjdk-arm64` (default `java` is 25; set `JAVA_HOME`/`PATH` explicitly). Use the upstream Leiningen at `/home/agent/tools/lein/lein` with `LEIN_HOME=/home/agent/tools/lein/home`; the Debian `/usr/bin/lein` silently drops transitive dependencies. Clojure CLI `clojure`/`clj` 1.12 is installed. Node 22. Headless Chromium for kaocha is at `/home/agent/browser-scratch/chromium-arm64/chromium` (the gate script wires it in). Postgres 18 on localhost:5432, users `postgres`/`postgres` and `test`/`test`. Network is restricted: Maven Central, Clojars, npm, PyPI, GitHub, services.gradle.org, plugins.gradle.org work; most other hosts return 403 "approval required"; report such a block rather than working around it.
8. **Scope discipline.** Do what the issue says; if you discover other work, list it under "Follow-ups" in your final report rather than doing it. If something blocks you, stop at a clean commit and report the blocker precisely (command, error, what you tried).
9. **Final report format.** Sections: Summary (3 lines), Commits (sha + subject), Gate results (per commit or final), Changes of note, Vetting entries added, Follow-ups discovered, Blockers. Keep it under 60 lines.
